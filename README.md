# BraveFrontier Offline — адаптация оригинальной игры

**Цель:** взять настоящий Android-клиент Brave Frontier Global 2.19.6 и восстановленный фанатами сервер, чтобы он работал на одном Android-телефоне без компьютера и интернета во время игры. В дальнейшем — пользовательские существа и игровые режимы.

**Это НЕ новый клон Brave Frontier.** Ранее сделанный независимый прототип признан неподходящим и вынесен в архивную ветку [archive/independent-prototype-v0.1.0](https://github.com/Domenklay/BraveFrontier_Offline/tree/archive/independent-prototype-v0.1.0). APK из старого релиза не является оригинальной игрой.


**Выгрузка ресурсов из LDPlayer 9 в приватный GitHub:** [пошаговая инструкция](docs/LDPLAYER_TO_PRIVATE_GIT.ru.md) и [автоматический инструмент](tools/ldplayer_to_private_git.py). В публичный репозиторий оригинальные игровые данные не загружаются.

**Актуальный прогресс и следующие действия:** [CURRENT_STATUS.ru.md](docs/CURRENT_STATUS.ru.md). На данный момент работоспособность полного офлайн-APK ещё не подтверждена.

## Эксперимент: встроенный сервер в тот же APK

Основная разработка ведётся в `main`; ветка `feature/embedded-server-bootstrap` сохраняет экспериментальную историю.

- `vendor/bf-private-server` и `vendor/bf-private-server-data` — **настоящие upstream-проекты** в виде зафиксированных Git-подмодулей. Их можно открыть в GitHub или получить командой `git clone --recurse-submodules`.
- `android-host/` — модуль Android-службы в отдельном процессе `:bfserver` и JNI-адаптер, который должен запускать существующий C++ сервер. Это **не новый игровой клиент**.
- `tools/build_android_native.py` — экспериментальный перенос upstream сервера в ARM64 .so.
- `tools/stage_payload.py` — локальная подготовка клиентских данных (не включены в Git).
- `tools/inject_host.py` — экспериментальное внедрение службы, native .so и контента в модифицированный **оригинальный** APK с повторной подписью.

Подробно: [что реально есть в исходниках](docs/SOURCE_INVENTORY.md), [архитектура одного APK и порядок сборки](docs/ONE_APK_INTEGRATION.md).

**Подтверждено:** успешно компилируется Java-библиотека службы и выполняются тесты Python-инструментов. **Пока не подтверждено:** native NDK сборка сервера, наличие полного клиентского пакета, запуск оригинальной Brave Frontier на одном телефоне в авиарежиме. Не выдавать Java-библиотеку за работающий игровой APK.

## Подтверждённый клиент BF Revive V20

Полученный от пользователя APK **реально исследован**, но по причинам авторских прав и приватности его бинарники **не добавлены в GitHub**.

- Package: \`sg.gumi.bravefrontier\`, versionName \`2.19.6.0\`, версия для ARM64.
- Размер 53 МБ; исходный фанатский API \`api.bfrevive.net\`, CDN \`cdn.bfrevive.net\`.
- Совпадение точных native offsets для 9 изменений. Проверенное преобразование направляет начальный API и host для дозагрузки на \`127.0.0.1:9960\` и переключает используемые инструкции HTTPS на HTTP.
- Новый [патчер BF Revive V20](tools/patch_bfrevive_v20.py) работает только с SHA256 библиотеки из этой сборки. Формирует **неподписанный промежуточный APK**, а НЕ готовую игру.
- [Полный анализ присланного APK](docs/BFREVIVE_V20_APK_AUDIT.md).

Проверка личной копии: \`python tools/patch_bfrevive_v20.py /private/bfrevive-V20.apk\`. Копия уже предоставлена для этой проверки; **повторно её запрашивать не нужно**. Проблема следующего этапа — Android NDK сборка готового сервера и полные клиентские \`content/mst\` (их нет внутри APK).

## Готовая основа

- Исходный клиент: **Brave Frontier Global v2.19.6** (пользовательская оригинальная копия, в GitHub не публикуется).
- [joppe2001/bf-private-server](https://github.com/joppe2001/bf-private-server): существующий сервер на C++23/Drogon с SQLite (AGPL-3.0), сюжет, задания, бои, призывы, эволюция и другие механики. Некоторые запросы ещё не реализованы.
- [joppe2001/bf-private-server-data](https://github.com/joppe2001/bf-private-server-data): восстановленные серверные данные.
- Патчер из upstream: [tools/patch_apk.py](https://github.com/joppe2001/bf-private-server/blob/main/tools/patch_apk.py): проверяет точную сборку клиента и переводит обращения на локальный сервер.

## Почему ещё нет автономного оригинального APK

Готовые проекты предполагают сервер на ПК или хостинге. Чтобы телефон работал автономно, нужно **портировать готовый сервер** на Android NDK и запустить его вместе с оригинальным клиентом, обеспечив локальную выдачу игровых ресурсов, таблиц и сохранений. Патч адреса на 127.0.0.1 сам по себе не создаёт работающий сервер.

Оригинальный модифицированный APK уже получен от пользователя и проверен. Из исходного `ServerCache.cpp` выделены **126 уникальных декодированных MST JSON**, необходимых для базовой загрузки сервера. По-прежнему нужны отдельно скачиваемые игровые ресурсы/клиентские таблицы: их нет в серверном репозитории и в присланном APK в полном объёме.

## Инструменты

- Запросить готовые исходники и данные: python tools/sync_upstream.py
- Проверить **присланный BF Revive V20**: `python tools/patch_bfrevive_v20.py /private/bfrevive-V20.apk`.
- Внутри сборочного процесса получить unsigned localhost-версию: `python tools/patch_bfrevive_v20.py /private/bfrevive-V20.apk --unsigned-apk build/patched-client.apk`.
- Проверить таблицы и ресурсы: `python tools/audit_content.py --decoded-mst /private/decoded-mst --client-content /private/game-downloads` (не загружает ничего в интернет).
- Для чистого оригинального APK с другим хешем есть отдельный инструмент `tools/check_client.py` — **не применять его вместо V20-патчера**.
- Зафиксированные версии: [upstream.lock.json](upstream.lock.json)
- Подробный план: [docs/PORT_PLAN.md](docs/PORT_PLAN.md)

Интегрированный пакет рассчитан на Android 8.0+ (API 26), соответствующий платформе текущей NDK-сборки. Старые Android 4–7 не поддерживаются этой экспериментальной версией.

Инструменты не переписывают игровой движок и не изменяют исходный клиент без отдельного осознанного шага. В публичный репозиторий не добавляем оригинальные APK/ресурсы.

# План: оригинальная Brave Frontier → Android offline

Дата: 2026-11-07. Целевое устройство: Android ARM64. Принцип: модификация существующей игры, не создание собственной с нуля.

## Факты из исходников

1. [bf-private-server](https://github.com/joppe2001/bf-private-server/blob/main/README.md) — сервер C++23 на Drogon, SQLite-сохранения, существующие обработчики логики и патчер клиентской версии v2.19.6.
2. [Патчер](https://github.com/joppe2001/bf-private-server/blob/main/tools/patch_apk.py) проверяет SHA и оригинальные байты lib/arm64-v8a/libgame.so; для локального режима меняет host, URL-схему и переподписывает APK. Не запускать на несовпадающей версии.
3. [Архитектура](https://github.com/joppe2001/bf-private-server/blob/main/docs/ARCHITECTURE.md): локальный сервер обслуживает /dls, /bf/gme/action.php, /mst, /content; сохраняет прогресс в SQLite. Рабочие конфигурации в upstream — ПК/хостинг.
4. [Начало работы](https://github.com/joppe2001/bf-private-server/blob/main/docs/GETTING_STARTED.md): помимо кодовых и восстановленных серверных таблиц отдельно нужны оригинальные клиентские ресурсы и decoded master tables.
5. Для игры на Android **без ПК** требуется подтвердить сборку или порт C++ сервера под Android NDK (зависимости, JNI, lifecycle, SQLite, раздача ресурсов), затем связать с оригинальным клиентом через loopback 127.0.0.1.

## Этап 1 — добиться работы оригинала

- [x] Выбрать существующий сервер и патчер, закрепить версии.
- [x] Перенести самостоятельный прототип в архивную ветку.
- [x] Написать read-only валидатор точного клиентского APK.
- [ ] Получить пользовательскую копию оригинального APK v2.19.6.
- [ ] Проверить SHA оригинального libgame.so.
- [ ] Получить локально client content + MST + decoded master tables законным способом, без публикации в GitHub.
- [ ] Собрать upstream-сервер и проверить на настоящем клиенте связь/логин/бои/сохранение.
- [ ] Зафиксировать какие запросы и игровые режимы не работают.

## Этап 2 — один автономный Android

- [ ] Проверить переносимую сборку Drogon/SQLite/C++23 и прочих зависимостей для NDK arm64.
- [ ] Запускать локальный сервер до первого запроса клиента, останавливать при выходе приложения.
- [ ] Отдавать все данные/ресурсы с телефона вместо внешнего CDN.
- [ ] Все сохранения хранить в приватной директории приложения.
- [ ] Согласовать запуск и переподпись оригинального APK, проверить совместимость с современными Android.
- [ ] Тестировать в авиарежиме без Wi-Fi и мобильного интернета, включая чистую установку и повторный вход.
- [ ] Подготовить поставку с ресурсами. Размер оригинального клиента и дополнительных данных может оказаться существенно больше 2 ГБ; итоговый способ установки определим после инвентаризации.

## Этап 3 — модификации оригинала

- [ ] Сохранить оригинальные существа, бои, звуки, меню и баланс по умолчанию.
- [ ] Использовать существующие balance overlays и формат серверных таблиц для новых существ и режимов.
- [ ] Отдельные сохранения и пользовательские наборы контента без изменения оригинального набора.

## Важно

Android INTERNET permission может быть необходим для соединения с localhost; его наличие само по себе не означает зависимость от внешней сети. Критерий — запуск и полная работа в авиарежиме, без обращений за пределы устройства.

Патчер без игрового APK, клиентских таблиц и работающего локального сервера **не** создаст полноценную офлайн-игру. Нельзя выдавать кодовый макет за реальную Brave Frontier. Соблюдать AGPL и авторские права на оригинальные ассеты.

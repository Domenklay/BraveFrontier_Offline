# LDPlayer 9 → ресурсный архив → приватный GitHub

Все команды ниже выполняются на ПК с LDPlayer 9. Исходный APK не передаётся в публичный репозиторий.

## 1. Подготовка

Нужны Python 3, Git for Windows с Git LFS, GitHub CLI (`gh`) и `adb.exe` из LDPlayer 9. Узнайте реальный путь `adb.exe`; пример ниже замените своим.
Игра должна успеть скачать данные. Не нажимайте «очистить данные» и не удаляйте приложение.

```powershell
$ADB = 'F:\LDPlayer\LDPlayer9\adb.exe' # пример: проверьте фактический путь
& $ADB devices -l
& $ADB shell pm path sg.gumi.bravefrontier
```

Если подключено несколько Android-устройств, во всех командах `pull` укажите `--serial SERIAL` после `--adb "$ADB"`.

## 2. Выгрузить кэш и файлы игры на ПК

В каталоге клонированного `Domenklay/BraveFrontier_Offline`:

```powershell
python tools/ldplayer_to_private_git.py pull --adb "$ADB" --output 'C:\BF_Archive'
```

Будут скопированы существующие `Android/data/<package>/files`, `Android/data/<package>/cache` и OBB. Команда не удаляет ничего из эмулятора, сохраняет исходные файлы в `C:\BF_Archive\raw` и не отправляет их в сеть. Если нужные ресурсы находятся в приватном каталоге приложения, включите Root в настройках LDPlayer и выполните дополнительно:

```powershell
# Не запускайте этот вариант поверх уже созданных одноимённых копий.
python tools/ldplayer_to_private_git.py pull --adb "$ADB" --output 'D:\BF_Private_Archive' --private-files --private-cache
```

**Важно для LDPlayer 9:** команда `adb root` может ответить `adbd cannot run as root in production builds` даже при разрешённом Root. Проверить доступ следует через `adb -s emulator-5554 shell su -c id` — нужен `uid=0(root)`. Скрипт автоматически проверяет `su` и при необходимости считывает файлы через поток `adb exec-out su -c tar`, не переписывая системный образ эмулятора. После обновления проекта (`git pull`) можно повторить `pull --private-files --private-cache`. Приватная копия остаётся только на ПК. В этих каталогах могут находиться секреты аккаунта. Если ADB-root недоступен, не переносите `shared_prefs` и базы данных обходными способами; сначала определим конкретные подпапки с ресурсами.

## 3. Подготовить кандидатов для Git

```powershell
python tools/ldplayer_to_private_git.py prepare --source 'C:\BF_Archive\raw' --output 'C:\BF_Archive\reviewed'
```

Первый вызов только показывает количество файлов и их общий размер. Для создания копии кандидатов:

```powershell
python tools/ldplayer_to_private_git.py prepare --source 'C:\BF_Archive\raw' --output 'C:\BF_Archive\reviewed' --confirm-review
```

Проверьте содержимое `reviewed` перед публикацией. Фильтр исключает известные каталоги учётных записей, ключи, логи и базы данных, но не гарантирует отсутствие секретов внутри неизвестных двоичных файлов. Особое внимание `.dat` и `.bin`. Часть неизвестных форматов может быть пропущена — это не означает, что они отсутствуют в игре.

## 4. Создать ОТДЕЛЬНЫЙ PRIVATE-репозиторий

На GitHub выберите `New repository`, имя `BraveFrontier_Assets` и visibility `Private`. Можно сделать это через авторизованный GitHub CLI:

```powershell
gh auth login
gh repo create Domenklay/BraveFrontier_Assets --private
git lfs version
```

Убедитесь, что репозиторий действительно приватный. Не добавляйте ресурсы к публичному `BraveFrontier_Offline`.

## 5. Записать проверенные файлы в Git и загрузить

```powershell
# Первый прогон готовит Git и LFS, показывает что будет загружено, но НЕ публикует.
python tools/ldplayer_to_private_git.py publish --source 'C:\BF_Archive\reviewed' --repo Domenklay/BraveFrontier_Assets

# После ручной проверки отобранного — фактическая отправка в приватный GitHub:
python tools/ldplayer_to_private_git.py publish --source 'C:\BF_Archive\reviewed' --repo Domenklay/BraveFrontier_Assets --push
```

Скрипт перед выгрузкой проверяет через GitHub CLI, что репозиторий PRIVATE, отказывается использовать публичный `BraveFrontier_Offline`, включает Git LFS для крупных игровых контейнеров и файлов >50 MiB, а также запрещает единичные объекты >2 GiB. Загруженные в Git LFS данные остаются на GitHub и учитываются в квотах владельца.

GitHub Free/Pro включает по 10 GiB LFS-хранилища и месячного трафика; если выгруженных ресурсов больше квоты, не отправляйте их все сразу. Для очень большого архива сохраняем полную копию локально, а в Git — только нужную часть, затем решим вопрос с дополнительным хранилищем.

## 6. Что прислать для продолжения интеграции

Достаточно ссылки на **приватный** репозиторий (и настроенного доступа, если требуется), либо отчёта о форматах и объёме файлов без личных данных. Я сопоставлю полученное с `docs/required_mst_2_19_6.json` и входом `tools/stage_payload.py`, определю недостающие таблицы и ресурсы. Репозиторий может быть приватным, но это не заменяет разрешений правообладателей на распространение оригинальных игровых материалов.


## Альтернатива для очень больших выгрузок: единый TAR с прогрессом

Если прежняя команда `ldplayer_to_private_git.py pull --private-files`
долго висит на `Pulling .../files`, а количество копируемых файлов
не увеличивается, остановите её через **Ctrl+C**. Не удаляйте данные
в Android и не отправляйте неполный дамп в GitHub.

В версии с 9 ноября 2026 добавлен отдельный инструмент,
который сохраняет весь приватный каталог `files` **одним двоичным TAR**
на Windows, вместо открытия большого числа отдельных файлов.
Он показывает размер выгрузки во время работы, не использует PowerShell
для двоичного перенаправления и отключается, если более двух минут
вообще нет данных. Частично полученная копия остаётся с суффиксом
`.part`; при ошибке не заявляется успех.

```powershell
cd C:\BF_Project
git pull --ff-only

python tools/pull_ldplayer_private_tar.py --adb "F:\LDPlayer\LDPlayer9\adb.exe" --serial emulator-5554 --output "C:\BF_GameDump\private_files.tar"
```

Требуется `adb -s emulator-5554 shell su -c id` → `uid=0(root)`.
Проверьте наличие достаточного свободного места: минимум объём
Android `files` плюс ~0,5 ГиБ. Команда **ничего не меняет**
в эмуляторе и не подключается к GitHub. Архив с приватными файлами
не предназначен для загрузки в Git: он может содержать токены и
персональные данные. Следующий этап — локальная выборка и проверка
содержимого, затем загрузка только отобранных файлов.

Если команда прерывается по отсутствию данных, пришлите сообщение
об ошибке и размер файла `private_files.tar.part`, не сам архив.


## Исправление повреждённого потока exec-out на LDPlayer 9

Если предыдущий вариант выгрузил гигабайты в `private_files.tar.part`,
но `inspect_ldplayer_tar.py` показал всего 1 файл/2 записи и
`remainder_mod_512` не равен нулю, **не переименовывайте** такой архив.
Из него нельзя считать успешно извлечёнными все ресурсы.

В LDPlayer 9 подтверждено свободное место для локального TAR на
`/sdcard`. Поэтому следующий инструмент создаёт TAR
**внутри эмулятора**, затем копирует его на Windows штатным
`adb pull`, сравнивает SHA256 устройства и ПК, проверяет количество
TAR-записей, конечные нулевые блоки, выравнивание и отсутствие
преждевременного конца TAR.

```powershell
cd C:\BF_Project
git pull --ff-only
python tools/pull_ldplayer_staged_tar.py --adb "F:\LDPlayer\LDPlayer9\adb.exe" --serial emulator-5554 --output "C:\BF_GameDump\bf-private-staged.tar"
```

Скрипт использует отдельный путь
`/sdcard/Download/bf-private-resources-stage-v1.tar` в эмуляторе;
**ничего не удаляет** ни из игровой папки, ни из старого дампа.
Если промежуточный архив уже существует, он не перезаписывается.
При проблемах со свободным местом или контрольными суммами процесс
выдаст ошибку и сохранит данные для диагностики.

Архив содержит все файлы из приватной папки, включая потенциальные
данные авторизации. Не отправляйте его в публичный/приватный GitHub
без очистки. Отдельно отберём из него графику, звуки и мастер-таблицы.

После успешной выгрузки внутренняя копия на `/sdcard/Download` может
быть удалена отдельно, только после ручного подтверждения целостности
Windows-копии. **Не удаляйте** каталог игры в `/data/data`.


## Сводный анализ полного проверенного TAR: 71 542 файла

Проверенная копия, не требующая повторной выгрузки:

`C:\BF_GameDump\bf-private-staged.tar`

```powershell
cd C:\BF_Project
git pull --ff-only
python tools/analyze_ldplayer_assets_tar.py "C:\BF_GameDump\bf-private-staged.tar" --output "C:\BF_GameDump\bf-asset-summary.json"
```

Анализатор не распаковывает и не отправляет файлы. Он проверяет
сигнатуры PNG/JPEG/WebP/OGG/ZIP и других форматов, считает распределение
по каталогам/расширениям, ищет совпадения имён обязательных MST JSON.
В отчёте только сводные количества и размеры; имена отдельных файлов
не включаются. Передавать можно только *сводный отчёт*, а не исходный
приватный TAR.

**Важно:** по проверке GitHub API от 9 ноября 2026 репозиторий
`Domenklay/BraveFrontier_Assets` оказался **Public**. Перед любой
передачей ресурсов требуется изменить его на **Private** через GitHub
Settings → General → Danger Zone → Change repository visibility.
Даже приватность GitHub не даёт дополнительных прав на распространение
чужих игровых ресурсов. Сначала отбираем нужные файлы и убеждаемся,
что в них нет личных данных.


## Анализ компонентов анимации (без распаковки)

После первичного отчёта по ~71 тыс. файлов используйте второй,
более предметный анализатор анимаций из Brave Frontier:

```powershell
cd C:\BF_Project
git pull --ff-only

python tools/profile_bf_asset_families.py "C:\BF_GameDump\bf-private-staged.tar" --output "C:\BF_GameDump\bf-animation-summary.json"
```

Отчёт учитывает:
- `unit_anime_<ID>.png`: исходный спрайт-лист юнита;
- `unit_cgg_<ID>.csv`: композиции кадров;
- `unit_idle_cgs_<ID>.csv`, `unit_atk_cgs_<ID>.csv`, `unit_move_cgs_<ID>.csv`: последовательности;
- `*.sam` и изображения вида `<stem>_<W>x<H>.png`;
- сигнатуры PNG, PNG с заголовком по смещению, сжатые и неизвестные PNG-именованные файлы;
- вероятные `*_mst.csv` по списку обязательных серверных таблиц (не равнозначны готовым JSON).

Используются только статистические агрегаты, без ID персонажей,
файловых имён и приватных данных. TAR не распаковывается и не передаётся.
Описание форматов и принципы анимации можно сверить с
`BluuArc/BFFrameAnimator` и `iammathew/SAJSON` на GitHub.
